# Типовые фичи: подводные камни

Использовать на Intake (вопросы и дефолты) и в рисках. Не вываливать всё — выбрать 3–5 релевантных.

## Карта / выбор точки (магазины, ПВЗ, адрес)
- SDK: Яндекс MapKit (РФ) / Google Maps / MapLibre — ключ, лицензия, квоты, санкционная доступность. Нативный view через `AndroidView` / `UIKitView`.
- iOS interop: жесты карты vs bottom sheet поверх, z-order `UIKitView`, производительность пинов.
- Загрузка по видимой области (bbox) + debounce движения камеры + отмена предыдущего запроса; кластеризация пинов при тысячах точек.
- «Ближайшие» — от пользователя, не от центра карты; лимит списка.
- Геолокация: разрешение, отказ (fallback — город/последний выбор), точность, «моё место».
- «Открыт сейчас» — лучше с бэка (праздники, спецграфики, часовые пояса).
- Последствия выбора: каталог/цены/остатки/корзина меняются — продуктовый вопрос.

## Лента (новости, товары, посты)
- Пагинация (cursor), бесконечный скролл, prefetch; дубликаты при вставке новых элементов.
- Гетерогенные карточки → контракт «тип блока + данные» (server-driven UI?) и поведение для неизвестного типа.
- Картинки/видео: кэш (Coil 3 / Kamel), плейсхолдеры, память, автоплей.
- Pull-to-refresh, «есть новые записи», сохранение позиции скролла при возврате.
- Офлайн: stale-while-revalidate, TTL.
- Метрики показов (impressions) — аналитика видимости элементов.

## Чат / мессенджер / поддержка
- Транспорт: WebSocket / SSE / long polling; реконнект, backoff, фон (на iOS сокет в фоне умирает → пуши).
- Порядок и дедупликация сообщений, локальный id → серверный id, статусы (отправлено/доставлено/прочитано).
- Офлайн-очередь отправки, ретраи, идемпотентность.
- Вложения: загрузка с прогрессом, размер, сжатие.
- Локальная БД как источник для UI (SQLDelight), пагинация истории вверх.
- Готовое SDK (поддержка) vs своё — часто дешевле взять SDK.

## Оплата / чекаут
- Google Pay / Apple Pay / СБП / платёжный SDK банка — нативно, отдельно на платформу.
- PCI DSS: номера карт не храним и не логируем, токенизация на стороне провайдера.
- 3DS — WebView/редирект, возврат в приложение (deeplink).
- Идемпотентность создания заказа/платежа, обработка «оплата прошла, ответ не дошёл».
- Правила сторов (цифровые товары → только in-app purchase).
- Тестирование только в sandbox; e2e затруднён.

## Камера / сканер (штрихкод, QR, документы)
- CameraX / AVFoundation, ML Kit / Vision — платформенная реализация за интерфейсом `Scanner`.
- Разрешения, отказ, фонарик, автофокус, слабое освещение.
- Производительность на слабых Android-устройствах; тестирование только на реальных девайсах.
- Fallback — ручной ввод кода.

## Bluetooth / BLE (устройства, весы, кассы)
- Полностью платформо-зависимо: сканирование, pairing, GATT; KMP-обёртки (Kable) — оценить зрелость.
- Разрешения (Android 12+ BLUETOOTH_SCAN/CONNECT, геолокация на старых), фоновые ограничения iOS.
- Нестабильность соединений, таймауты, реконнект; зоопарк Android-устройств.
- Нужен реальный стенд с устройством для QA — риск и строка в оценке; эмулятор не поможет.

## Пуши / уведомления
- FCM / APNs (+ RuStore/HMS при необходимости), регистрация токена, обновление токена.
- Разрешение (Android 13+, iOS), deeplink из пуша, cold/warm start.
- Тихие пуши и ограничения фона на iOS.
- Зависимость от бэка/CRM-команды (сегменты, шаблоны).

## Авторизация / профиль
- OAuth/OTP по SMS, автоподстановка кода (SMS Retriever / iOS one-time code).
- Хранение токенов в Keychain / EncryptedSharedPreferences за `SecureStorage`; refresh-токен, гонки при параллельных 401.
- Биометрия — платформенно.
- Логаут = очистка всех кэшей фич.

## Поиск
- Debounce, отмена запросов, подсказки, история (локально), пустой результат.
- Поиск на бэке vs локальный; опечатки/морфология — зона бэка.

## Медиа (видео, аудио, сторис)
- ExoPlayer/Media3 vs AVPlayer — платформенно за интерфейсом; жизненный цикл, фон, PiP.
- Кэш/прелоад, трафик, автоплей в ленте.
